## 3. 已完成的编辑器通道（供后续参考，勿再走弯路）

- 插件页面 SDK 的 endpoint 会被拼成 `/api/v1/plugins/extensions/<插件名>/<endpoint>`
- 该路径由 AstrBot 的 `_call_plugin_extension` 在 `star_context.registered_web_apis` 里匹配，
  匹配不到就返回「未找到该路由」
- 因此**插件必须自己注册 Web API**：`context.register_web_api("/<插件名>/config", handler, ["GET","POST"], desc)`
  —— route 必须带插件名前缀，页面只传相对路径 `config`
- ❌ 不要再用「上传文件 + 轮询」通道：真实环境返回 `403 Insufficient API key scope`
- ❌ 不要再猜 `/api/plugins/<id>/config` 这类路径：那是 AstrBot 自己的接口，不在插件页面权限内

## 4. 命令别名可配置（用户要求：不想每次都找人改）

新增配置项 **`command_aliases`**（text，多行，一行一个子命令）：
```
背包|仓库,行囊
档案|金币,资料
商店|鱼饵,道具
```
格式：`规范子命令|额外别名（逗号分隔，全角逗号也认）`

实现要点：
- 在 `main.py` 的 `fishing` 分派**之前**做一次「别名 → 规范子命令」归一化（现在别名是硬编码在 `elif key in (...)` 里的）
- **校验与容错**（必须做，否则容易做出死命令）：
  - 别名与已有的**规范子命令**冲突 → 跳过并告警（不允许把「背包」映射到别处）
  - 两个子命令争同一个别名 → 先到先得 + 告警
  - 目标子命令不存在 → 跳过该行 + 告警
  - 空值 / 全部写坏 → 回退内置默认（即现有代码里已有的那批别名，行为不变）
- 默认值 = 现有别名，用**等价性测试**卡死（从配置构建的别名表与内置默认逐项一致）
- 加入 `DEFAULTS_SYNC_EXCLUDE_KEYS`（与其他内容表一致）
- 编辑器页面加一个「⌨️ 命令」标签页（表格：子命令 / 别名，点着改）
- README 补一节（行格式 + 示例 + **当前可用子命令清单**），与玩家金币编辑一起发 v1.10.0

## 5. 自定义命令与行为（用户要求："能自定义命令和行为就更好了"）

在「⌨️ 命令」标签页里，除别名外再加一张 **`custom_commands`**（text，多行，一行一条）：

```
快捷签到|执行:签到
领奖|发送:今天也要加油！兑换码：ABC123
新手礼包|执行:签到;背包
查鱼|执行:查 鲤鱼
```

格式：`命令名（不含 /钓鱼）|动作:内容`

**动作类型只做两种**（易懂、可控、不易做出死命令）：
- `发送:` → 直接回复一段文本（支持 `{金币}`、`{等级}` 之类的简单占位符，取当前玩家数据）
- `执行:` → 依次执行**已有的子命令**（分号分隔，可带参数，例如 `查 鲤鱼`）

**必须做的校验**（否则用户会配出跑不通或死循环的命令）：
- 命令名与已有子命令 / 别名 / 其它自定义命令冲突 → 跳过 + 告警
- `执行:` 里的子命令必须真实存在（用现有子命令表校验）→ 不存在则跳过该行 + 告警
- **禁止自定义命令互相调用**（不允许 `执行:` 指向另一条自定义命令）→ 防递归
- 条数上限（例如 50 条）与文本长度上限，防止把配置写爆
- 空值 / 全部写坏 → 该配置项为空即可（自定义命令为空 = 没有额外命令，不影响内置命令）

**实现要点**：
- 在 `fishing` handler 分派前，先把首参数依次过一遍：别名归一化 → 自定义命令匹配
- `执行:` 的实现是"替换参数后走一次正常分派"（一层，不递归）
- 内置子命令永远优先（自定义命令不能覆盖内置行为）

**UI**：同一标签页里两张表（别名 / 自定义命令），都能点着改、加行删行；MUST 每改一处立刻跑 `node test_editor_ui.js`

**文档**：README 写清格式、两种动作、占位符清单、校验规则与平台无关的注意事项
