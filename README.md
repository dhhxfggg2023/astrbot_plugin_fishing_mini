# 群钓鱼 · astrbot_plugin_qq_fishing

**v1.7.0** ｜ 适用于 **QQ 群**的钓鱼养成小游戏，基于 **AstrBot v4.x** 插件规范开发
（已在 AstrBot v4.28.1 + Python 3.12 上实测）。

**232 种水族 · 16 个钓点 · 8 档鱼饵 · 6 档鱼竿 · 5 档鱼种品质 · 5 档个体品质 ·
6 种变异 · 53 个成就 · 天气系统 · 鱼市行情 · 不定时订单 · 水族馆养成 ·
群内排行榜 · 里程碑 · 最佳渔获纪录 · 随机小插曲 · QQ 官方按钮**

**所有功能都挂在 `/钓鱼` 一条指令下**，只注册 1 个指令名，避免和别的插件撞名。

> 🎣 **下竿不要钱**：空钩免费，花钱只在买鱼饵；鱼饵在下竿时从库存扣 1 个
> （买的时候已经付过钱，不会再重复收一次饵钱）。
>
> 💾 **数据可以随时存档/导出/回滚**：全在 WebUI 的插件配置里点，不用发指令；
> 每天自动存档、一天一份不覆盖。
>
> 🎛️ **还带一个网页版数据编辑器**（插件页面 →「数据编辑器」）：在浏览器里改鱼池、
> 鱼饵、鱼竿、道具、钓点与核心数值，也能建/恢复/删除/改名玩家存档 ——
> 见 [🎛️ 数据编辑器页面](#-数据编辑器页面)。

## 📊 数值平衡（先说结论）

这套数值是重新标定过的，**每一档都比上一档强，但跨度受控**：

| 阶段 | 每竿毛收益 | 饵成本 | 每竿净收益 |
| --- | --- | --- | --- |
| 新手：竹竿 / 新手村 / 空钩 | 13.2 | 0（免费） | **+13.2** |
| 新手+：竹竿 / 新手村 / 面包屑 | 15.8 | 1 | +14.8 |
| 前期：碳素竿 / 竹林溪流 / 蚯蚓 | 26.3 | 2 | +24.3 |
| 中期：溪流竿 / 山间湖泊 / 玉米粒 | 54.9 | 6 | +48.9 |
| 后期：龙纹竿 / 近海渔场 / 虾饵 | 176.8 | 12 | +164.8 |
| 末期：星辉竿 / 深海海沟 / 活饵 | 1586.5 | 22 | +1564.5 |
| 终局：神话竿 / 极光冰渊 / 秘制饵 | 5972.5 | 45 | **+5927.5** |

（以上为 2 万次蒙特卡洛实测，`test_local.py` 里会自动跑并断言区间）

**设计意图**：

- **新手绝对亏不了**：空钩下竿 0 成本，平均 +13/竿；
  最便宜的面包屑 1 金、蚯蚓 2 金，用得起也划得来（钓不到好东西只是慢，不会倒贴）。
  空钩上鱼率只有三成，带饵之后明显更容易咬钩（饵越贵越明显，界面上只给「手气」星级）。
- **每档鱼竿/钓点的边际收益 > 成本**：例如碳素竿 400 金买 5% 价值加成，在竹林溪流约 250 竿回本——回本变慢是有意的，钓鱼本身才是主要收入。
- **鱼饵是真实取舍**：饵越贵，稀有鱼与个体品质的期望越高（界面上只给「手气」星级，
  不给具体数值），所以「要不要上贵饵」是个判断，而不是无脑升级。
- **金币有真实去处**：鱼竿 40,400 + 钓点 1,072,700 + 背包扩容 4,200 ≈ **1,117,300 金币**
  的一次性回收（另有水族馆扩建 23,000），金币不会无限堆积。
- **等级按累计钓获算**，曲线是**指数型**（`base × (ratio^(L-1) − 1) / (ratio − 1)`，
  默认 `base=5`、`ratio=1.08`，上限 50 级）：
  10 级要累计 62 条、20 级 207 条、30 级 520 条、45 级 1785 条、50 级 2652 条。
  前段比旧的二次曲线更平缓（新人好追），后段反超并急剧变陡 —— 目的就是**卡住最高进度玩家**。
  三个参数（`level_xp_base` / `level_xp_ratio` / `level_xp_growth`）都能在 WebUI 里调，
  `ratio` 填 `1.0` 会退化成等差（线性）曲线。
- **越往后越慢，但不会被卡死**：钓点门槛 = 等级 + 上一个钓点图鉴开到八成
  （隐藏生物不算在内）+ 一次性金币；被拒绝时 `/钓鱼 钓点 解锁 <名>` 会把还差什么一次列清楚
  （列表视图里未解锁的钓点只显示 `🔒 + 名称`，不提前报进度）。
- **概率一律不显示**：鱼饵/鱼竿/天气的加成用「手气 ★★★☆☆」这类定性表达，
  玩家不会去算概率，而是去玩。

## 🌦️ 天气与时段（每天不一样）

每天（按配置时区）随机一种天气，**全天不变**。用 `/钓鱼 今日` 一眼看完今天的看点。

| 天气 | 概率 | 效果 |
| --- | --- | --- |
| ☀️ 晴朗 | 30% | 无加成，什么都有可能上钩 |
| ⛅ 多云 | 24% | 窗口 ×1.05，逃脱 ×0.95，幸运 +2% |
| 🌧️ 下雨 | 16% | 少见 ×1.4、稀有 ×1.5、传说 ×1.3，幸运 +4% |
| 🌫️ 起雾 | 12% | 稀有 ×1.6、传说 ×1.8、神话 ×1.5，窗口 ×0.85 |
| 🌙 月夜 | 10% | 传说 ×1.7、**神话 ×2.0**，幸运 +6% |
| 💨 大风 | 8% | 窗口 ×0.75、逃脱 ×1.25（更难，但少见/稀有更多） |

实测：极光冰渊的传说鱼出现率从晴朗的 **2.7%** 提升到月夜的 **4.3%**，神话鱼从 **0.18%** 提升到 **0.46%**（高稀有度鱼的刷新权重整体下调过，「月夜」这类加成因此更值钱）。

## 📈 鱼市行情（每天 1~2 种高价）

每天随机 1~2 种鱼成为「今日高价」，卖价 **+50% ~ +120%**，跨天刷新：

```
📈 今日高价：🐟草鱼+84%　🐟泥鳅+51%
```

卖鱼时自动结算，并在回复里标明「📈 行情加成 +N」，方便你知道今天该留什么鱼。

## 🧹 卖光光与锁定

- `/钓鱼 卖光光` — **一次清空背包**换金币，并**自动跳过** 🔒 你锁定的鱼
  （会告诉你留下几条、怎么解锁）。
- `/钓鱼 锁定 1 2` — 锁定不想被卖的鱼（展示时带 🔒 标记）。
- `/钓鱼 解锁 1` / `/钓鱼 解锁` — 解锁指定序号 / 全部解锁。
- 想只卖一部分：`/钓鱼 卖 鲤鱼`（按鱼名）、`/钓鱼 卖 1 2 3`（按序号）。

> ℹ️ v1.3.0 起**移除了「卖 垃圾」（只清小鱼）这个玩法**：
> 输 `/钓鱼 卖 垃圾` 只会得到一句「已经去掉」的说明，不会再动背包里的任何鱼。

```
🧹 卖光光 12 条 → 1,240 金币
💰 余额 3,860
🔒 另有 3 条锁定的鱼留在背包里（/钓鱼 解锁 1 可以解锁）
```

## 🐳 Docker 部署（AstrBot + 本插件一体镜像）

仓库里带了 `Dockerfile` / `docker-compose.yml` / `.env.example`，
一个容器就能把 AstrBot 和这个插件一起跑起来（基于官方镜像 `soulter/astrbot:latest`）。

```bash
cp .env.example .env          # 填机器人凭据（见下表）
docker compose up -d --build  # 首次构建
docker compose logs -f astrbot  # 看到「管理面板已启动」后访问 http://<服务器IP>:6185
```

| `.env` 变量 | 作用 |
| --- | --- |
| `TZ` | 时区，中国填 `Asia/Shanghai` |
| `DASHBOARD_PORT` | 管理面板在宿主机上的端口（默认 6185） |
| `ASTRBOT_DASHBOARD_INITIAL_PASSWORD` | 首次初始化时的面板密码（留空 = 自动生成并打印在日志） |
| `QQ_APPID` / `QQ_SECRET` | QQ 官方机器人凭据（QQ 开放平台 → 开发设置） |
| `QQ_ENABLE_GROUP_C2C` / `QQ_USE_MARKDOWN` | 群聊 @ 与 markdown（按钮依赖它，建议 `true`） |
| `ONEBOT_WS_PORT` / `ONEBOT_WS_TOKEN` | OneBot v11 反向 WS（NapCat / Lagrange 连 `ws://<IP>:6199/ws`） |
| `FISHING_CONFIG_OVERWRITE` | `1` = `.env` 强行覆盖 AstrBot 里已有的值 |
| `FISHING_FORCE_SYNC` | `1` = 每次启动都用镜像里的插件覆盖数据卷里的插件 |

### ⚠️ 关于「机器人 key 放进 .env」

先说结论：**这个插件本身没有任何密钥**。QQ 官方机器人的 `appid`/`secret`、
OneBot 的 access token 都属于 AstrBot 主程序，存在 `data/cmd_config.json`
的 `platform` 数组里（插件只注册 `/钓鱼` 指令，不碰平台连接）。

而且 **AstrBot v4.28.1 不读 `.env`**（源码里没有 dotenv 依赖）。所以本仓库的做法是：

1. `docker compose` 把 `.env` 变成容器环境变量；
2. 容器入口脚本 `docker/entrypoint.sh` 调用 `docker/inject_cmd_config.py`，
   在启动时把这些值写进 `data/cmd_config.json` 的对应平台条目；
3. 写之前自动备份 `cmd_config.json.bak-<时间戳>`，**日志里绝不打印密钥**。

写入策略（都能在 `test_docker_deploy.py` 里看到断言）：

- `appid` / `secret` / `ws_reverse_token` 等**密钥字段**：只在当前为空时写入，
  已有值不动（想强制覆盖设 `FISHING_CONFIG_OVERWRITE=1`）；
- `QQ_ENABLE_GROUP_C2C` / `QQ_USE_MARKDOWN` 这类**开关**：只要在 `.env` 里写了就以 `.env` 为准，
  没写就保持 AstrBot 里的现有配置；
- 平台条目不存在时自动新建（含 `id`），已存在则只改需要的字段。

> `.env` 已在 `.gitignore` / `.dockerignore` 里排除，仓库只提交 `.env.example`。
>
> 🧪 **诚实说明**：本机没有 Docker，镜像**没有做过真机 `docker build` 验证**。
> 脚本逻辑（注入/不覆盖/备份/容错/compose 语法）由 `test_docker_deploy.py` 离线断言，
> 官方镜像事实（基础镜像、`WORKDIR /AstrBot`、`CMD ["python","main.py"]`、无 ENTRYPOINT、6185 端口）
> 来自 AstrBot 仓库的 Dockerfile，但请你在有 Docker 的机器上先跑一次 `docker compose up -d --build`。
> 来自 AstrBot 仓库的 Dockerfile；镜像由 **GitHub Actions 在真 Docker 环境里构建并冒烟测试**
> （见下节），你也可以自己 `docker compose up -d --build`。
> 如果你更习惯原生方式，也可以在 WebUI 里直接配机器人，然后把插件目录丢进 `data/plugins/`。

### 用 CI 构建好的镜像（免本地 Docker）

推送到 `main`（或手动触发 workflow）后，GitHub Actions 会自动构建镜像并推到 GHCR：

```bash
docker pull ghcr.io/dhhxfggg2023/astrbot_plugin_qq_fishing:latest

docker run -d --name astrbot \
  -p 6185:6185 -p 6199:6199 \
  -v "$PWD/data:/AstrBot/data" \
  --env-file .env -e TZ=Asia/Shanghai \
  ghcr.io/dhhxfggg2023/astrbot_plugin_qq_fishing:latest
```

- ⚠️ 首次使用前，到
  [package 设置](https://github.com/users/dhhxfggg2023/packages/container/astrbot_plugin_qq_fishing/settings)
  把可见性改成 **Public** —— GHCR 的包默认是 private，别人匿名 `docker pull` 会 404。
- 每次构建都会在**真容器里跑冒烟测试**：插件文件齐全、`_conf_schema.json` 是合法 JSON、
  容器内 `py_compile` 通过、入口脚本能把插件同步进 `data/plugins/`
  （并确认 `docker/`、`Dockerfile` 这些开发文件没被带进运行目录）。

### 数据与迁移

`./data` 里是全部状态：`data_v4.db`（玩家数据、KV）、`config/`（插件配置）、
`plugins/`（插件本体）、`backups/`（自动存档）。删容器不丢数据。

想把现在这套桌面版的存档搬进容器：停掉两边 → 把原 `data/` 整个拷到项目的 `./data` →
`docker compose up -d`（首次启动 entrypoint 会把镜像里的插件同步进去）。

## ⚡ 体力与连钓

**体力取代了原来的「冷却时间」**：每钓一次扣 **1 点**，体力随时间自己攒回来
（默认每 **45 秒**回 1 点，也就是原来那竿冷却），**上限 20 点**——攒够了就能一口气钓个爽。

```
⚡ 体力 12/20
　下一点恢复：还需 18 秒
　满体力能连钓 12 次（/钓鱼 12）
```

- `/钓鱼` 单竿：扣 1 点体力 + 1 个当前鱼饵
- `/钓鱼 10` **连钓 10 次**：一次扣 10 点体力 + 10 个饵，逐条列出每竿结果并给汇总
  （`🧮 渔获估值`、`✅ 上鱼/空竿/杂物/跑掉` 统计、剩余体力）；次数上限由
  `multi_cast_max` 控制（默认 20，写成 `/钓鱼 9999` 会被拦下）
- 连钓里**不弹拉线互动**：传说/神话按逃脱率直接判定，跑掉会标出来
- 体力或鱼饵不够时**整批拒绝**，不会先扣一半；背包快满时会截断到剩余格数，
  并明确写着「只扣了 N 份」
- 想关掉这套机制（回到想钓就钓）：把 `stamina_max` 或 `stamina_regen_seconds`
  任一填 **0** 即可，`/钓鱼 体力` 会显示「本服未启用体力限制」

> 老玩家更新后**按满体力开始**，不会因为改版被挡在门外。
> 每个玩家的体力是惰性结算的（按时间戳现算），不需要后台定时任务。

## 📖 水族图鉴（232 种，不都是鱼）

除了鱼，还有虾、螺、蟹、贝、水母、海龟、蛙、鳗，甚至「破靴子」「易拉罐」
这类捞上来的东西——**16 个钓点各有一批自己的物种**。

图鉴的三种看法（**只列已经钓到的**，没收集的不占屏、也不剧透）：

```
/钓鱼 图鉴              各钓点的收集进度（✅ = 已够八成，可以前往下一个钓点）
/钓鱼 图鉴 山间湖泊      这个钓点里已收集的鱼 + 末尾「还差 N 种（共 M 种）」
/钓鱼 图鉴 详 [页码]     已收集鱼的完整清单（每页 15 种）+ 末尾总汇总
```

集齐某个品质会有**永久价值加成**，集齐全部鱼种再加一档（见下文）。

## ✨ 两套品质 + 三维养成

### 鱼种品质（固有，**不可改变**）
`常见 < 少见 < 稀有 < 传说 < 神话`，决定基础价值与是否需要拉线。

### 个体品质（**可提升**）
`⚪普通 🟢优良 🔵稀有 🟣极品 🌟传说`，权重 `44/28/16/9/3`，影响售价倍率。
饲料改不了它（饲料只加三维），但 **🔮洗髓丹**能提高掷出好个体的概率。

### 三维数值（养成核心）
每条鱼有 **肉质 / 灵性 / 光泽**（0~100），按鱼种品质生成不同区间：

```
售价 = 基准价 × 属性系数 × 个体品质倍率 × 个体差异 × (鱼竿+钓点倍率)
属性系数 = 1 + (肉质×0.45 + 灵性×0.30 + 光泽×0.25 − 60) / 100
```

投喂饲料提升三维 → 直接涨价。单条鱼最多喂 10 次。
**注意**：个体差异与装备倍率在上钩时固定，投喂只会让鱼涨价，绝不会掉价。

## ⚡ 拉线互动（只有最高两档）

- **常见 / 少见 / 稀有**：直接上钩，零操作。
- **传说 / 神话**：咬钩后进入拉线窗口。

| 落点（相对最佳时机） | 评价 | 品质幸运 | 逃脱率 |
| --- | --- | --- | --- |
| 距最佳点 < 半个完美区 | 🎯 完美 | +30% | ×0.3 |
| 距最佳点 < 1.5 倍 | 👍 良好 | +10% | ×1.0 |
| 更远（压线） | 😅 偏差 | +0% | ×1.6 |

- 窗口时长随机，并按鱼的 `diff` 缩放；**最佳点位每条鱼都不同**
  （锦鲤正中 0.50、金龙鱼偏早 0.38、深渊鲸偏晚 0.68）。
- **超时 = 鱼跑了**（钓费不退）。
- 跨群保护：别的群发「拉」不会误触发。

## 🎁 杂物与漂流瓶

**一竿只出一样**：先按鱼饵的咬钩率判定有没有中鱼 —— 中了就是鱼，
没中才看钩子上有没有带物件（**14%** 概率，`item_drop_chance`）：

```
咬钩率（bait_hook_rates）──中了──▶ 上鱼（这一竿必定是鱼，不会被杂物抢走）
        └──没中（1-p）──▶ 杂物率（item_drop_chance）──中了──▶ 钩上带个物件（不计渔获）
                                      └──没中──▶ 空手而归
```

🌿海草 · 🥾破靴子 · 🥫铁皮罐 · **🍾漂流瓶** · 🐚星纹贝 · 🪙沉水古币 · 🎁沉船宝箱

- 完全免费的空钩（没挂饵、也没开钓费）**不会出杂物**，防止零成本白刷。
- 配置写法很宽容：`worm:0.80`、`蚯蚓:0.8`、`worm:80`（百分数）、全角逗号都认；

## 💾 数据管理（存档 / 导出 / 导入 / 清除）

内测阶段数据格式还可能变，所以插件把**每个玩家的数据都包了一层信封**，
并且提供完整的存档与回滚能力 —— **全部在 WebUI 里操作，玩家侧没有任何指令**。

### 每个玩家都是一份自带版本的信封

```json
{
  "__fishing_player__": 1,      // 信封版本
  "user_id": "123456",
  "data_version": 5,            // 玩家数据结构版本
  "saved_at": 1789650000,
  "saved_text": "2026-09-18 04:00:00",
  "data": { "...玩家数据..." }
}
```

读档时**两种形态都认**：老数据（没有信封的裸 dict）照常读入，下次保存自动升级成信封。
所以内测期间换版本、换机器都不会因为格式变化丢数据。

### 存档目录（在插件里，专门安放并注明）

```
data/plugins/astrbot_plugin_fishing_mini/
└── backups/
    ├── README.md                    ← 说明每个子目录的用途与保留规则（插件自动维护）
    ├── index.json                   ← 快照清单（配置页面的状态栏读它）
    ├── daily/2026-09-17.json        ← 每日存档：一天一份，**永不覆盖**
    ├── daily/2026-09-17_01.json     ← 同一天再存会加后缀，依然是独立文件
    ├── auto/2026-09-17_0600.json    ← 按时存档（默认每 6 小时）
    ├── manual/20260917-213000.json  ← 手动存档（配置里点「立即存档」）
    ├── players/<用户ID>.json        ← 单个玩家导出
    └── exported/…                   ← 配置里下载用的副本
```

存档目录可以改（`backup_dir`），默认就在插件目录下，**换机器直接连目录一起拷走**。

### 在 WebUI 里怎么操作

**插件 → 群钓鱼 → 配置 → 数据管理**：

| 配置项 | 作用 |
| --- | --- |
| `data_status` | 插件回写的状态：玩家数、存档数量、最近快照、存档目录、上次操作结果 |
| `editor_status` | 数据编辑器页面读的状态（JSON 字符串，插件回写：存档清单 / 玩家数 / 下次自动存档 / 可改的数值键）。**手改没有意义**，下一次保存就被覆盖 |
| `data_action` | 选一个操作（立即存档 / 导出全部玩家 / 导出单个玩家 / 从快照恢复 / 恢复单个玩家 / 导入上传的存档 / 清除单个玩家 / 清除全部玩家数据），**保存即执行**，执行完自动复位为「无」 |
| `data_target` | 目标：玩家 ID（导出 / 清除单个玩家）、快照文件名（`latest` 或留空 = 最新快照），或 **`快照名/玩家ID`**（把某个玩家恢复到指定快照） |
| `data_confirm` | 危险操作（清除 / 恢复）必须勾上，否则会被拦住 |
| `backup_import_file` | **上传存档文件**：把存档 JSON 拖进来（支持整份快照或单个玩家文件） |
| `backup_export_file` | **导出存档文件**：导出结果出现在这里，点文件名即可下载 |
| `enable_auto_backup` | 自动存档总开关 |
| `backup_daily_hour` | 每日存档时间点（默认 4 点）：当天过了这个点存一份 |
| `backup_interval_hours` | 按时存档间隔（默认 6 小时，0 = 关闭） |
| `backup_keep_daily` / `backup_keep_interval` | 每日存档保留天数 / 按时存档保留份数（0 = 永久） |
| `backup_dir` | 存档目录（留空 = 插件目录/backups/） |

几个关键设计：

- **危险操作先自动存档**：清除和恢复之前都会先存一份「恢复前自动存档」，
  点错了还能用快照倒回来。
- **每日存档绝不覆盖**：一天一份，同一天多次执行会带时间后缀，历史快照一直留着。
- **保存配置 = 热重载 + 立刻执行**（AstrBot 保存插件配置会重载插件），
  所以选完操作点「保存」就完事，不需要重启。
- **自动存档循环**只做三件事：到点存每日档、到间隔存按时档、刷新状态文本；
  出错只记日志，不影响钓鱼。

## 🎛️ 数据编辑器页面

插件自带一个**网页版数据编辑器**，不用手写配置文件，直接在浏览器里改鱼池、鱼饵、
鱼竿、道具、钓点与核心数值，顺手管理玩家存档。

### 入口

**AstrBot 面板 → 插件 → 群钓鱼 → 页面 → 「数据编辑器」**

路径是 `pages/editor/index.html`：AstrBot 会自动发现 `pages/<目录名>/index.html`
（不需要额外元数据），并注入桥接 SDK、把当前主题写进 `<html data-theme="dark|light">`。
页面标题的中文来自 `.astrbot-plugin/i18n/zh-CN.json` 里的 `pages.editor.title`
（这是 AstrBot 唯一认的 i18n 路径，**不是** `<插件>/i18n/`）。

### 能改什么

| 标签页 | 对应配置 | 行格式 |
| --- | --- | --- |
| 🐟 鱼池 | `fish_defs` | `id｜名称｜稀有度｜基准价｜分布｜说明` |
| 🗺️ 钓点 | `location_defs` | `id｜名称｜emoji｜解锁等级｜解锁金币｜价值倍率｜说明` |
| 🪱 鱼饵 | `bait_defs` | `id｜名称｜emoji｜单价｜一组数量｜品质幸运｜稀有度权重｜解锁等级｜需要鱼竿｜说明` |
| 🎣 鱼竿 | `rod_defs` | `id｜名称｜emoji｜价格｜价值加成｜幸运加成｜解锁等级｜描述` |
| 🎒 道具 | `item_defs` | `id｜名称｜emoji｜价格｜说明｜效果（key=值;分号分隔）` |
| ⚙️ 数值 | 20 个核心数值键 | 体力、连钓上限、鱼价总闸、各项概率与曲线… |
| 💾 存档 | `backups/` | 新建 / 恢复 / 删除 / 改名 / 刷新，以及自动备份设置 |

表格支持行内编辑、搜索、排序、筛选、批量改价 / 改稀有度 / 改分布、导出与导入 JSON。
**只有上面这几类能改**：管理项（`data_*`、`backup_*`、`editor_status`）页面改不了 ——
插件侧有白名单，越权请求会被明确拒绝并把原因回写到页面上。

### 保存通道的原理（重要）

AstrBot 的插件页面 SDK 只有 `apiGet / apiPost / upload / download / subscribeSSE`，
**没有 PUT**，而「写插件配置」只有 `PUT /api/plugins/{id}/config` —— 页面够不着。
所以这套页面走的是「**上传文件 + 插件轮询**」：

```
页面  --upload("/api/files")-->  data/attachments/fishing_editor_bridge.json
                                     ↑ 固定文件名，重复上传即覆盖（永远只有最新一条指令）
                                     │
                            插件每 1.5 秒 stat + 读一次这个文件
                                     │  nonce 与上次不同才执行
                                     ↓
                     写配置 / 建快照 / 恢复 / 删除…（动作白名单）
                                     │
页面  <--apiGet 插件配置--------  editor_status（插件回写的 JSON 字符串）
```

* **1~2 秒生效**：点「保存并生效」后页面会说「已提交，1~2 秒后生效」，
  并在 2 秒后自动重新载入，从 `editor_status` 里读**插件的真实执行结果**。
  看到「已提交」只代表上传成功，不代表配置已经写完 —— 这一点页面不会含糊其辞。
* **不会重复执行**：每条指令带一个随机 `nonce`，插件记住上次处理过的那个；
  插件重启时也会先「播种」一次现有文件的 nonce，避免把上一次的指令又跑一遍。
* **坏数据不卡住**：解析失败或动作不认识，一样记 nonce 并回写中文错误，
  轮询循环永远不退出。
* **上传失败会明说**：把 HTTP 状态、服务端返回的原因、出错端点都显示出来，不静默。

指令文件的落点由 `ASTRBOT_ROOT` 决定：`<AstrBotRoot>/data/attachments/`；
目录还不存在时插件静默跳过（每秒一次 `stat`，几乎零开销）。

### 存档管理

存档卡片显示**真实文件名、类型、备注、时间、玩家数、大小**：

| 按钮 | 实际动作 |
| --- | --- |
| ＋ 新建存档 | 立刻把全部玩家存成一份 `manual/` 快照（可写备注名） |
| ↩ 恢复 | 整份快照恢复；也可以只恢复单个玩家（恢复前**自动再存一份**，恢复错了还能倒回来） |
| 🗑 删除 | 删除该快照（删除前**自动再存一份**，防手滑） |

| ⬇ 下载信息 | 下载这份存档的**信息**（名字/时间/玩家数）。要拿玩家数据本体，请用「插件配置 → 导出存档文件」或直接取 `backups/` 里的同名文件 |

### 离线预览

在没有 AstrBot 桥接的情况下直接打开这个 HTML（本地 `file://` 预览、改样式时），

* 用内置演示数据渲染，编辑、排序、校验、批量操作照常可用；

## 🛡️ 健壮性（针对「数据一定要存好」）

- **所有写操作都走 `_save_player` 并回报结果**：失败会提示「⚠️ 保存失败」。
- **列表类改动显式回写 `player[...]`**：曾因为 append 到分离的局部列表而丢鱼
  （真实踩过的 bug），现在全部统一回写。
- **不可重入锁的自死锁也踩过**：`asyncio.Lock` 不能重复获取，
  `/钓鱼 商店 扩容` 转发时曾把自己锁死。现在拆成
  `_cmd_backpack_upgrade`（自己加锁）+ `_do_backpack_upgrade`（调用方持锁）两层。
- **数据自愈**：修复被改坏 / 旧版本 / 类型错误的数据，异常全部吞掉回退默认值。
- **并发保护**：每个玩家一把锁，同一玩家的操作串行执行，不会互相覆盖存档。
- **互动不留垃圾**：等待用 future 在 `finally` 清理，插件卸载时取消所有悬挂等待。
- **日志规范**：统一用 AstrBot logger，不用 `print`。

## 🔧 开发踩过的坑（都留在代码注释里）

1. **指令参数按空格依次填充形参**。`/钓鱼 卖 锦鲤 2` 必须声明成 `(a1, a2, a3)`。
2. **参数声明为 `str` 再自行转换**，否则用户输入非数字会在解析阶段抛错。
3. **`metadata.yaml` 的 `author` 必须是非空字符串**；`astrbot_version` 不能带 `v` 前缀。
4. **异步生成器不能用带值的 `return`**，互动结果用「最后 yield 一个 dict」回传。
5. **等待玩家输入要先注册再提示**，否则手快的玩家会在竞态窗口丢输入。
6. **随机数要在正确时机只掷一次**：个体差异与装备倍率必须上钩时固定，
   否则每次投喂重掷会导致「喂了反而掉价」。
7. **配置里的字段都是字符串**，`_safe_number` / `_safe_int` 必须能解析 str，
   否则鱼饵幸运值、逃脱率表会全被解析成 0。
8. **`asyncio.Lock` 不可重入**，同一玩家锁内不要再调用会加同一把锁的函数。
9. **测试里判断互动状态要按 user_id 精确匹配**，只看「表非空」会命中上一轮残留条目。
10. **`get_astrbot_root()` 无环境变量时回退 `os.getcwd()`**，
    测试脚本已强制指向临时沙箱，避免在插件目录生成 `data/`。

## ❓ 常见问题

**Q：发了 `/钓鱼` 没反应？**
A：检查唤醒前缀（默认 `/`）；确认插件在 WebUI 里已启用。

**Q：提示「背包满了」？**
A：先 `/钓鱼 卖`（或 `/钓鱼 水族馆 放`），或 `/钓鱼 商店 扩容` 扩容。

**Q：想快点去深海海沟？**
A：需要 16 级 + 25,000 金。等级靠累计钓获，湖泊/近海是必经之路。
嫌慢就在配置里调小 `location_defs` 里的 `level_gate`/`gold_gate`。

**Q：咬钩了没来得及拉？**
A：鱼跑了，钓费不退。想更宽容就调大 `window_min`/`window_max`，
或调小 `rarity_escape_chance`。

**Q：觉得赚太快/太慢？**
A：先看 README 开头的平衡表；主要旋钮是 `fish_cost`、`order_reward_mult`、
`location_defs` 的价值倍率、以及各鱼竿的价格。

**Q：怎么给玩家回档 / 迁移服务器？**
A：把 `data/plugins/astrbot_plugin_fishing_mini/backups/` 整个拷过去就行；
只想给某个人回档：配置里「导出单个玩家」→ 拿到 JSON → 在目标机器上
「上传存档文件」+「导入上传的存档」。想整体回滚到某个时间点：选「从快照恢复」。

**Q：数据存在哪？**
A：`data/data_v4.db` 的 preferences 表，scope=`plugin`、
scope_id=`dhhxfggg2023/astrbot_plugin_qq_fishing`、key=`player_<用户ID>`。

**Q：发指令机器人完全不回复，日志里写着 `is not in the session allowlist`？**
A：这是 **AstrBot 的白名单拦截**，跟插件无关——事件在流水线的
`WhitelistCheckStage` 就被 `stop_event()` 了，任何插件都收不到。
注意分辨「默认配置」和「生效配置」：AstrBot v4 支持**配置方案（AB 配置档案）**
并按会话路由（`data/data_v4.db` 里的 `umop_config_routing`），
你看 `cmd_config.json` 里白名单是空的也照样会被拦。
处理办法（改完**必须重启后端**，白名单是启动时快照的）：
1. WebUI → 配置 → 选中该平台路由到的那个方案 → 白名单 →
   「白名单 ID 列表」里加上日志中打印的 Session ID
   （`平台ID:消息类型:会话ID`，群号也参与比对）；
2. 或者把该方案的「启用白名单」关掉；
3. 或者把「白名单 ID 列表」清空（空 = 放行全部）。

> ⚠️ QQ 官方机器人的会话 ID 是 **openid**，跟 QQ 号不是一回事：
> 白名单里放 `123456789` 这种 QQ 号，对 `qq_official` 平台无效，
> 必须放日志里打印的那个 `default_xxxx:GroupMessage:<openid>`。

**Q：升级后钓点变少了 / 某几种鱼怎么都钓不到 / 钓费变成 0？**
A：这是**旧版配置残留**。AstrBot 只在配置文件里**缺键**时补新的默认值，
**已经存在的键会原样保留**，所以 `location_defs`、`rod_defs`、`fish_cost`
还是你上次保存的旧数值。

**现在不用再手点「重置配置」了**：插件用「默认值指纹」判断代码里的数值有没有变过，
变了就自动把新默认值同步进你的配置（`defaults_sync_mode` 默认 `auto`）。

| 档位 | 行为 |
| --- | --- |
| `auto`（默认） | 同步**数值与内容**（钓费、物价、鱼竿/钓点/鱼饵/道具表、各种概率与倍率）；`data_*` / `backup_*` 这些管理设置**不受影响** |
| `all` | 连功能开关一起重置，等同「重置配置」 |
| `off` | 不同步，保留你自己改过的所有值（想手动掌控时用） |

> 启动日志会写一条「配置已同步 N 项到新版默认值（模式 auto，指纹 xxxxxxxx）」，
> 你可以据此确认机制生效。只想临时保留自己的改法时，把它设成 `off` 即可。

**Q：我设置了咬钩率 80%，为什么感觉钓上来的鱼没那么多？**
A：现在**咬钩率就是上鱼率**（中了鱼不会被杂物抢走）。但请注意三点：
1. 咬钩失败的那部分里，还有 `item_drop_chance`（默认 14%）的概率钩上杂物 —— 那不是鱼；
2. 传说/神话咬钩后要走拉线，拉崩了会跑掉（`rarity_escape_chance`）；
3. **深水图还有钓点难度系数**（`location_hook_factors`）：实际上鱼率 = 咬钩率 × 系数。
   前 3 张图系数 ≥ 1.0（必出鱼），越往后越低（极光冰渊 0.44）；
4. 配置写错会导致数值不符：现在漏写/写坏的鱼饵按 **0.30** 处理（旧版本会错误地变成 100%），
   并会在日志里点名「哪个键不认识、可用键有哪些」。

## 🐟 在配置面板里改鱼与物品

打开 **WebUI → 插件 → 群钓鱼 → 配置**，这些内容表现在都能直接编辑：

| 配置项 | 内容 | 一行一条，字段格式 |
| --- | --- | --- |
| **`fish_defs`** | **鱼池（默认 232 条）** | `id\|名称\|稀有度\|基准价\|分布\|说明` |
| `location_defs` | 钓点 | `id\|名称\|emoji\|解锁等级\|解锁金币\|价值倍率\|说明` |
| `rod_defs` | 鱼竿 | `id\|名称\|emoji\|价格\|价值加成\|幸运加成\|解锁等级\|说明` |
| `bait_defs` | 鱼饵 | `id\|名称\|emoji\|单价\|一组数量\|品质幸运\|稀有度权重\|解锁等级\|需要鱼竿\|说明` |
| `item_defs` | 道具 | `id\|名称\|emoji\|单价\|说明\|效果(键=值;键=值)` |

**`fish_defs` 的分布字段**：`钓点:权重` 逗号分隔，一条鱼可以属于多个钓点，
`*` 表示"所有钓点"，权重省略就是 1.0。钓点可以写 id 也可以写中文名。

```
carp|鲤鱼|常见|120|lake:1.0,sea:0.6|鲤鱼的经典款
kun|鲲|神话|26000|abyss:0.05|北冥有鱼，其名为鲲
big_fat_fish|大肥鱼|稀有|120|*:0.15|深海里最肥的一条
```

**改价的三种方式**（优先级从高到低）：
1. `fish_value_overrides`：`鲲:30000,锦鲤:200` —— 按鱼名或 id 单条覆盖
2. `fish_defs` 行内基准价 × `fish_value_mult` —— 全局闸门（`1.5` = 全部鱼贵 50%）
3. 内置数据

**注意**：
- 行内权重是「基础权重」，运行时会再乘 `rarity_spawn_weights` 里那个稀有度的权重
  —— 所以逐条微调和整体调爆率可以并存 ✅
- 格式写错的行会被跳过并在日志里点名（不会让插件起不来）；
  **分布为空的鱼会被跳过**（否则会出现"加了鱼却永远钓不到"）
- 留空或全部写坏 → 自动回退内置鱼池，绝不会没鱼可钓
- **内容表不会被升级覆盖**：`defaults_sync_mode: auto` 只同步数值类配置，
  鱼池/钓点/鱼竿/鱼饵/道具这些你编辑过的内容会原样保留，官方新增内容由
  `content_auto_merge` 增量补齐
- 成就与随机插曲仍在 `_game_data.py`（含达成条件逻辑，改文件即可，顶部有逐字段说明）

## ⌨️ 空格容错（怎么写都能用）

所有子命令的参数都用统一的 token 解析，**多打空格、少打空格、参数个数变化都能正确工作**：

```
/钓鱼 卖 1 2 3          ✅
/钓鱼 卖  1    2   3    ✅ 多余空格自动忽略
/钓鱼 卖 1,2,3          ✅ 逗号也当分隔符
/钓鱼 卖 1-9            ✅ 区间写法
/钓鱼 卖 全部           ✅
/钓鱼 水族馆 放 1 3 5    ✅ 批量放入
/钓鱼 商店 买 蚯蚓 3     ✅ 买 3 组
```

**少打空格也能用**（子命令与参数粘在一起）：

```
/钓鱼 卖1 2        ✅ = /钓鱼 卖 1 2
/钓鱼 帮助2        ✅ = /钓鱼 帮助 2
/钓鱼 背包1        ✅ = /钓鱼 背包 1
/钓鱼 商店买蚯蚓2   ✅ = /钓鱼 商店 买 蚯蚓 2（2 组）
/钓鱼 水族馆放1     ✅ = /钓鱼 水族馆 放 1
/钓鱼 水族馆取1-3   ✅ = /钓鱼 水族馆 取 1-3
/钓鱼 用高级饲料1   ✅ = /钓鱼 用 高级饲料 1
/钓鱼 卖 鲤鱼3      ✅ = /钓鱼 卖 鲤鱼 3
/钓鱼 订单交1       ✅ = /钓鱼 订单 交 1
/钓鱼 去湖泊        ✅ = /钓鱼 去 湖泊
```

> 只有「看起来像参数」的粘连才会被拆开：`/钓鱼 帮助x` 仍然回
> 「不认识『帮助x』这个用法」，不会被悄悄当成「帮助」——
> 打错字时给提示比猜你的意思更安全。

鱼名支持**模糊匹配**：`鲤鱼`、`小鲫`、`七彩` 都能命中对应鱼种。

参数**大小写不敏感**（`Cast` / `cast` / `CAST` 等价），中英文别名也都能用。

### 🎣 「下竿」的写法随你

不想记 `下竿` 这个词也没关系，下面这些**全都等于抛一竿**：

```
/钓鱼              /钓鱼 钓        /钓鱼 钓鱼
/钓鱼 下竿          /钓鱼 抛竿      /钓鱼 甩竿
/钓鱼 下钩          /钓鱼 抛        /钓鱼 cast
/钓鱼 fish         /钓鱼 fishing
```

拉线时同理：`拉` / `拉线` / `收` / `收线` / `提` / `提竿` / `拽` / `pull` / `p` 都认。

> 打错的子命令不会被静默忽略，而是回一句「不认识「xxx」这个用法」并附上
> 最常用的几条指令，避免玩家以为是插件坏了。

## 🐞 已修复的重要漏洞

**水族馆展出加成无限叠加（经济漏洞）**
早期版本每次「取出」都会按 `base_value` 再加一次加成并累加到 `live_bonus`，
于是「取出 → 放入 → 取出」可以无限刷钱。
现在每条鱼带一个 `pond_claimed` 标记，**展出加成终生只能领一次**；
15 轮反复放入/取出的实测价值稳定在 `base × 1.2`（不再是滚雪球）。

**「卖 垃圾」这个玩法（已移除）**
它最初是为了「被误当成鱼名」而加的：`/钓鱼 卖 垃圾` 会去找一条叫「垃圾」的鱼并报错。
后来做成了「只卖 8 金币以下的小鱼」，但和 `/钓鱼 卖光光` 的定位重叠、
规则又不好解释（为什么这条小鱼没被卖掉？），所以在 **v1.3.0 直接移除**：
`/钓鱼 卖 垃圾` 只回一句「已经去掉」并指向 `/钓鱼 卖光光`，不会动背包里的任何鱼。

**经济为负（新手越钓越穷）**
早期新手村每竿净收益 −2.8 金币，新玩家会一直亏。
现在通过「钓费 10 → 8」+「鱼价整体 ×1.35」修正为 **+2.1/竿**，
既不会亏死也不会暴富（详见文首平衡表）。

**鱼饵「双倍消耗」**
早期版本下竿时既扣掉 1 个鱼饵库存、又按饵的单价收了一次金币，
等于买了 5 个蚯蚓还要每竿再付一次饵钱。
现在下竿只扣库存（钱在买饵时已经付过），并加了回归测试：
「一次下竿只扣 1 个饵」「钓费为 0 时不再扣钱」。

**饵用完了却不换、也不说**
早期只有「裸下竿」会临时改用空钩，且那句提示只在**钓上鱼**时才显示，
鱼跑掉时玩家只看到掉钱；存档里的「当前鱼饵」也一直显示已经用完的饵。
现在：饵耗尽会写入存档切成空钩、提示在鱼跑掉时同样显示，
并新增 \/钓鱼 换饵 <名字|空钩>\ 主动切换。

**子命令回复被整段发两遍**
分派器里 `async for` 循环里多写了一行 `yield result`，导致每个子命令的输出
（帮助、背包、订单……）都会被发送两次，聊天里看起来像刷屏。
现在循环体只 `yield` 一次，并在两个测试脚本里各加了一条
「单条消息类子命令只回一条」的回归断言。

**里程碑记录写坏存档导致玩家数据被重置**
`_repair_player()` 里 `raw.get(milestones)` 少写了引号（把字段名当变量），
每次读取存档都会抛 `NameError`，触发「数据修复失败 → 重置」分支，
玩家的金币、鱼篓、成就全部清零。
现在该处已改为字符串键，并且 `milestones` / `best_records` / `egg_*` 计数
都有专门的**存档往返断言**（写入 → 修复 → 校验还在）。

## 🤖 QQ 官方机器人适配

本插件的输出**统一走 `event.plain_result`**，AstrBot 会自动处理平台差异：

- **QQ 官方机器人（`qq_official` / `qq_official_webhook`）**：
  适配器默认把文本包成 `markdown` 载荷发送（平台配置 `use_markdown`，默认开），
  失败时内部会自动降级成纯文本重试（`_send_with_markdown_fallback`），
  所以本插件的纯文本输出在任何配置下都能送达。
- 插件在 `_reply()` 里预留了统一出口，将来要接模板消息只需要改这一个方法。
- 每条渔获会记录来源平台（`last_platform` 字段），方便排查平台相关问题。

**关于「官方适配的命令唤起」**：QQ 官方机器人要求指令以 `/` 开头才会走指令链路，
本插件的唯一指令就是 `/钓鱼`（带唤醒前缀），并且所有子命令都挂在它下面
（`/钓鱼 帮助`、`/钓鱼 背包`……），因此在官方机器人上不需要额外注册。
真机上建议直接发 `/钓鱼 帮助 1` 验证链路。

**关于按钮（v1.2.0 已支持）**：AstrBot v4.28.1 的消息组件里**没有 Button / Keyboard**
（可用的是 Plain / At / Image / Reply / Json 等），所以本插件在**平台允许时**
直接调用 botpy 的原生接口发一条带 `keyboard` 的消息
（[官方文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/trans/overview.html)）：

```python
await event.bot.api.post_group_message(
    group_openid=..., msg_type=0, content=text,
    msg_id=..., msg_seq=...,          # 被动回复
    keyboard={"content": {"rows": [{"buttons": [btn]}]}},
)
```

按钮一律用官方的**指令按钮**（`action.type = 2`，`permission.type = 2`，
`data = "/钓鱼 拉"`）：

- 点击后等价于玩家发出 `data` 里的指令，走 AstrBot 正常的指令链路，
  **不需要**处理 `INTERACTION_CREATE` 回调（那需要改 AstrBot 适配器，插件改不了）；
- 群里点击会把指令插到输入框，单聊里 `enter: true` 直接发送（官方行为）；
- 发送失败 / 非 QQ 官方平台 → 自动退回纯文本，正文里写清该发什么指令，
  所以其它平台体验不受影响。

出现按钮的位置：咬钩提示（`拉线！`）、抛竿结果（`再来一竿`/`看背包`/`今日`/`卖光光`/`帮助`）、
随机小插曲（两个选项各一个按钮）。

**接入步骤**（简述）：

1. 在 QQ 开放平台创建机器人，拿到 AppID / AppSecret。
2. AstrBot WebUI → 平台 → 新增 `qq_official` 适配器，填入凭据并启用。
3. 在开放平台配置好沙箱/正式环境的频道或群。
4. 发 `/钓鱼 帮助 1` 测试；若没响应，先在 WebUI 看该平台适配器的日志。

> 官方机器人对**主动消息**有限制：适配器需要一个「最近收到的消息 ID」
> 才能回复（`send_by_session` 在没有 msg_id 时会跳过），
> 除非该适配器允许群内主动推送。本插件的群播报、咬钩提示、成就推送
> **全部发生在「你发了消息之后」的同一条回复链里**，因此不受此限制；
> 带按钮的消息同样带上了 `msg_id` + `msg_seq`，属于被动回复。
